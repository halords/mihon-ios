## Architecture (user-confirmed)
LOCAL-FIRST, NO ACCOUNT (like Android Mihon): everything on-device — library/categories/progress/history/settings in IndexedDB + localStorage, downloaded chapters in Cache Storage. No server state, no sign-in. SW precaches the full app shell (vite-plugin-pwa generateSW) so the installed PWA opens fully offline. navigator.storage.persist() requested on first launch and available in Settings, with a storage usage readout in Settings. Step 6 acceptance test: downloaded chapters readable end-to-end in airplane mode. JSON export/import + .tachibk import are the device-to-device safety net — both prominent in Settings.

## Improvements round 2.1 (reader axis-lock, paged zoom, continuous flow, 2026-11-05)
User report (screenshot, mid-chapter): the reader drifted/panned sideways while scrolling at fit width; horizontal movement must be impossible except when zoomed. "Continuous" clarified mid-round: webtoon chapters must flow into each other with no end screen.

- Fix 1 (done, 4fb8d28): axis-lock. ROOT CAUSE found: `.reader-pages { margin-inline: -16px }` — a full-bleed trick from when the screen had horizontal padding; `.screen--full` has none, so the strip was 32px wider than the scroll container, giving a permanent 32px horizontal scroll range (the drift), worsened by `.screen--full { overflow: auto }` (both axes) and the reader root's INLINE `overflow: 'auto'` overriding any CSS lock. Changes: `.screen--full` (reader-only class, verified) is now overflow-x: hidden / overflow-y: auto / overscroll-behavior-x: none / touch-action: pan-y; `.reader-pages` margins removed (strip is exactly container width) + max-width: 100% + touch-action: pan-y; `.reader-pages img` max-width: 100%; reader root inline overflow/overscroll REMOVED (class governs; inline overflow returns only while paged-zoomed). In-flow children audited (end card max-width 720, empty block, paged surface) — none can exceed container width. Build exit 0.
- Fix 2 (done, c7a78ec): paged-mode zoom, Mihon-style. Zone buttons route through handleZoneTap: single-tap actions (prev/center-chrome/next) are held ~300ms; a second tap inside the window cancels the action and double-tap-zooms to 2× centered on the tap point (transform translate+scale, origin 0 0, applied via ref to the page img — no React re-render during pan). clampEdge keeps the scaled page covering the viewport (centered on any axis where it is smaller). While zoomed: zone buttons unmount, a [data-zoom-layer] overlay (touch-action: none, pointer capture) owns pan gestures with per-move clamping; single tap does nothing; double-tap resets to fit (axis lock re-engages); root overflow hidden. Zoom is per-chapter — resetZoom() runs on chapter change, page change (prev/next/seek), and mode toggle. Webtoon untouched: no zoom, strictly vertical. Build + tsc exit 0.
- Fix 3 (done, 727067c): continuous chapter flow in webtoon mode. The strip is now a window of FlowSegments (anchor chapter + appended next chapters, each under a slim .chapter-divider labeled with the chapter name; NO end-of-chapter interstitial in webtoon). Loader's downloads-aware page resolution was factored into loadChapterPages() and is shared by appends, so appended chapters read from Cache Storage in airplane mode exactly like opened ones. Appends trigger from an IntersectionObserver sentinel (~1.5 viewport rootMargin) with a scroll-proximity fallback in handleScroll; guarded by appendingRef + cKey duplicate check; next chapter = next READABLE chapter (external skipped); a failed/0-page next chapter shows a retry card, and no-next-chapter appends a "You're at the latest chapter" card with Back to details. Active-chapter tracking: handleScroll resolves the segment + page under the viewport midpoint; chrome title/page counts/progress, the seek slider, chapter-state lastPage and history (putHistory on every throttled save) follow the ACTIVE segment via flowRecord() — same db helpers and writesRef serialization as recordProgress, no parallel store. Crossing into a later chapter force-records the previous chapter's last page (marks it read, same as finishing did). Resume unchanged: opening a chapter seeds it as the anchor at its saved page and flows forward. Chapter-exit cleanup flushes the ACTIVE segment's progress (not the anchor's) and revokes appended segments' blob URLs (anchor's are revoked by the [data] effect); toggleMode flushes + discards the flow and restarts the anchor chapter at its saved page in paged mode.
